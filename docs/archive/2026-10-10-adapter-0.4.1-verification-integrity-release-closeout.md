# Adapter 0.4.1 Verification Integrity Release Closeout

Date: 2026-10-10
Status: released

## Scope

0.4.1 was originally prepared in June (#54, structured signed-auth
errors) but never published: the WordPress.org trunk stayed on 0.4.0
while 44 commits accumulated on master. Per the WordPress.org release
gate's fold rule, this release ships all of them:

- The verification-integrity arc with Governance Core 0.3.0: #94
  (ADR-012 execution-attached verification reads) and #95 (ADR-013
  Core-recorded supplement for readbacks that could not be verified, so
  objects created inside the same batch verify through Core-minted
  evidence instead of degrading).
- The Core 0.2.x/0.3.0 REST contract adoption (#89): recoverable
  preflight handoffs, `app_auth_expired` hints, the 429 retry relay,
  `contract:read` fallback, audit offset passthrough.
- The 2026-10 AI review backlog hardening wave (#80-#84), including
  server-side `ability_id` enforcement and governed-write lock
  hardening.
- The zh_CN catalog completion (#57) and the behavior-preserving
  controller split into eight domain services (#63, #67, #70-#76).

The boundary is unchanged: reads route through the WordPress Abilities
API, governed writes through Core proposal and commit-preflight truth,
final writes only via allowlisted execution profiles, and the unified
approve-and-execute action remains administrator-session-only.

## Release Process Notes

1. The June 0.4.1 changelog entry predated the arc and was re-folded at
   release time (#97) to cover the actual shipped scope.
2. `plugin-check:release` reads the Local.app MySQL socket from
   `WP_DB_SOCKET` (not `WP_CLI_MYSQL_SOCKET`); one `release:verify` leg
   failed on a database connection before this was recorded.
3. The verification-supplement behavior probe ships in the repository
   but not in the wp.org package (`.distignore` excludes `tests/`), the
   same as the other behavior probes.
