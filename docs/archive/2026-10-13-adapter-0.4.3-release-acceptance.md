# Adapter 0.4.3 Release Acceptance

Date: 2026-10-13
Status: candidate; verification in progress; not published.

## Release scope

WordPress.org trunk and tags were checked directly and ship 0.4.2. Candidate
0.4.3 includes Adapter PR #109 (explicit delete-attachment execution profile)
and #110 (complete local acceptance, safe package restoration and socket support).
The non-numeric `limit` fix is already shipped in 0.4.2 and remains a required
runtime regression check on `/proposals` and `/read-requests`.

The delete-attachment profile is usable only on hosts providing that Toolkit
ability. This Adapter candidate adds no ability callback, Core approval state,
Cloud runtime or generic executor. Core approval and commit preflight remain
required; `core_proxy_execute=false` and `commit_execution=false` remain intact.
The local Toolkit master currently does not register delete-attachment, so
successful execution of that new profile is not claimed by this acceptance.

## Required verification

- Source tests, PHPStan and coding standards.
- i18n, WordPress.org guard, route-documentation guard and Plugin Check.
- Current-source release package install/activation and original-plugin restore.
- Full WordPress smoke without skipped grant-dependent cases, including both
  `limit=abc` HTTP 400 / rest_invalid_param checks.
- Real signed HTTPS create-draft fixture: reject client self-approval, obtain
  Core approval using a separate WordPress administrator test context, commit
  through the signed client, check Core evidence/result recording, reject a
  duplicate execution, verify WordPress readback and remove the test draft.
- Central cross-repository quality matrix before closeout.

The administrator approval step is an integration-test simulation through Core's
existing approval route, not evidence of an operator clicking the admin UI.
